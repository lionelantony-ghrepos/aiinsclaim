## Surfaces

- **Dashboard:** `src/app/(app)/(staff)/dashboard/page.tsx` — 4 KPI cards (claims by state, avg cycle time, STP rate, SLA breaches), 4 charts (cycle time by LOB, fraud distribution, override rates, SLA breaches by status), backlog table; supervisor/admin only (`requireRole`)
- **Audit viewer:** `src/app/(app)/(staff)/claims/[id]/audit/page.tsx` — chronological decision chain (rule evals, agent runs, state changes), expandable cards with JSON I/O, CSV export button
- **SQL views:** `ljadev/drizzle/0001_kpi_views.sql` — 8 views: `claims_by_state`, `cycle_time_by_lob`, `stp_rate`, `sla_breach_counts`, `override_rates_by_agent`, `fraud_band_distribution`, `queue_backlog`, `claim_audit_chain`
- **Queries:** `src/lib/db/queries/kpi.ts` — helper functions wrapping `db.all<T>(sql`…`)` on each view

## Contracts

- Server action `exportAuditChainToCsvAction(claimId: string)` → `Result<{ csv: string }>` (in `claims/[id]/actions.ts`)
- CSV format: 12 columns (event_number, event_type, event_id, event_at, actor, version_id, matched_rule_ids, agent_id, from_status, to_status, inputs_summary, outputs_summary); header row + data rows; escaped commas/quotes
- Query functions return typed arrays from views; handle SQLite numeric coercion

## Rules

- No BR-* rules evaluated
- Reads `rule_audit_log`, `agent_runs`, `claim_state_history`, `sla_timers`, `fraud_scores`, `tasks` via views (read-only aggregates)

## How to extend

- **Add KPI:** create new view in a migration SQL file, add query function in `kpi.ts`, integrate into dashboard page
- **Override rate calculation:** currently checks `json_extract(outputs_json, '$.is_override')` — expand logic if more override patterns emerge
- **Dashboard charts:** swap CSS progress bars for recharts library if design requires more complex visualizations
- **Audit CSV columns:** add/remove columns in `exportAuditChainToCsvAction` CSV builder

## Ops

- **Env vars:** none new
- **Migration apply:** run `npx tsx scripts/apply-kpi-views.ts` to apply SQL views (one-time or after view schema changes); drizzle-kit push fails on views (expected)
- **Seed dependency:** dashboard KPIs accurate only after full seed (`npm run seed`); empty DB shows zero counts
- **Performance:** views are not materialized; large claim volumes may require indexing on `claim_id`, `event_at`, `status` columns in base tables
