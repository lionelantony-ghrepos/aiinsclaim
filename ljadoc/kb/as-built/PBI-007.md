## Rules

- BR-DOC-001 guard on draft→submitted (FNOL completeness) and assessment_complete settlement gate
- BR-TRIAGE-001, BR-STP-001, BR-AUTH-001 guards on respective transitions
- Operational guards: `open_info_request`, `info_received`, `payment_created`, `closure_checklist`, `denial_approval`

## How to extend

- Add rows to `seed/definitions/transitions.ts`; re-seed — no code change required for unguarded moves
- Register new guard functions in `guards.ts` and reference `guard_code` in transition seed
- Call `transitionClaim` from server actions (PBI-009 submit, PBI-011 triage STP, etc.)
- Do not hard-code transition matrix in TS — keep DESIGN §4.2 in DB
