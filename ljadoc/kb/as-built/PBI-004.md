## Surfaces

- Auth scope: `src/lib/auth/scope.ts` (`canAccessClaim`, `canWriteClaim`, `assertCanWriteRules`), typed errors in `src/lib/auth/errors.ts`
- Isolated sqlite helper (tests only): `src/lib/db/isolated.ts` — not re-exported from `src/lib/db/index.ts`
- Append-only triggers: `src/lib/db/append-only-triggers.ts`
- Queries: `src/lib/db/queries/` (re-exported from `src/lib/db/index.ts`)
- Tests: `tests/db/pbi-004-*.test.ts`, `tests/lib/auth/scope-write.test.ts`, harness `tests/helpers/isolated-db.ts`
- No UI in this PBI

## Contracts

- Query helpers take `(db: Db, user: SessionUser, …)` so callers/tests do not need cookies
- Errors: `RulesWriteForbiddenError`, `AppendOnlyViolationError`, `TaskResolutionReasonRequiredError`
- Generated reference: [generated/packages.md](../generated/packages.md)

## Rules

None evaluated — schema and access only. Decision tables stay in `parameters` / rules tables for later PBIs (IDs only; no thresholds copied here).

## How to extend

- New entity reads: add a module under `src/lib/db/queries/` and apply `isStaffRole` / `claimantClaimsFilter` (join `claim_parties` + `parties`)
- Rules/parameters mutations must call `assertCanWriteRules`
- Do not add update/delete for append-only tables
- Do not query the app `ljadev/data` file from tests — use `openIsolatedDb` + `drizzle-kit push` on a temp path

## Ops

- Env: `DATABASE_PATH` (temp file for TC-004-01)
- Seed / fixtures: none in app seed; tests insert their own rows into isolated DBs
- Test harness: `tests/helpers/isolated-db.ts` runs `npx drizzle-kit push` with `DATABASE_PATH`
