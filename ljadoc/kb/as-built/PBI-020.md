## Shipped vs spec

| Item | Status | Notes |
| --- | --- | --- |
| Comms drafter | shipped | AGT-COMMS drafts acknowledgement, information-request, and decision-letter communications from the selected template and claim summary. Drafts are editable, saved to the mock outbox, and only marked mock-sent after an explicit human action; no external delivery is performed. |
| Contract and guardrails | shipped | Output tone/reading-level, template grounding, and decision-letter coded-reason validation are enforced. Invalid output retries once, then degrades to a manual-review task without blocking the claim. |

## Surfaces

- Route: `/claims/[id]?tab=communications` (the legacy `?tab=comms` alias is accepted)
- Panel: `src/app/(app)/(staff)/claims/[id]/_components/communications-panel.tsx`
- Server actions: `draftCommunication`, `updateCommunicationDraft`, and `sendMockCommunication`
- Mock outbox: `notifications` rows with `kind=comms`, `delivery_status=draft|mock_sent`
- Agent: `src/lib/agents/comms.ts`; prompt `src/lib/agents/prompts/comms/v1.md`

## Contracts

- Zod schemas: `src/lib/schemas/agents/comms.ts` (`CommsAgentInputSchema`, `CommsAgentOutputSchema`, `CommsDraftRequestSchema`, `CommsUpdateDraftSchema`, `CommsSendSchema`)
- Gateway contract: AGT-COMMS input/output is parsed before persistence; `agent_runs` stores redacted input, output, status, and `prompt_version=v1`
- Human review contract: edits are persisted as draft overrides; explicit mock send records delivery and updates the agent-run outcome
- Generated reference: [generated/](../generated/) (refreshed with `npm run docs:generate`)

## Rules

- BR-* decision tables introduced: none; AGT-COMMS proposes content and does not decide claim outcomes.
- Coded decision-letter reasons are read from the configured denial reason set and must be present in the claim record and generated/sent body.
- Entitlements: `requireRole()` permits intake agents, adjusters, supervisors, SIU analysts, and admins; claim access remains server-scoped.

## How to extend

- Add a new communication type to the shared comms schemas, template registry, prompt contract, and contract tests together.
- Keep template and claim-summary grounding in `src/lib/agents/comms.ts`; do not move it into the client panel.
- Preserve the mock-only send boundary until a separately reviewed delivery integration exists.

## Ops

- Env vars: none added.
- Seed / fixtures: `tests/fixtures/gateway/comms-valid.json` and `comms-schema-invalid.json`; local seed data provides workbench claims and demo staff accounts.
- Failure operations: two schema failures produce a manual-review task; repeated configured failures can disable AGT-COMMS and notify admins. All invocations are logged in `agent_runs`.
- Test harness: Vitest uses an isolated SQLite clone and a mocked Gateway; Playwright exercises the seeded `/claims/[id]` communications tab.
